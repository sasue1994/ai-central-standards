## Agent workflow — ALWAYS follow this order

### Step 1 — Clarify before anything else
หากคำสั่งกำกวมในข้อใดข้อหนึ่งต่อไปนี้ ให้ **หยุดถามก่อน** ลงมือ:
- ขอบเขตไม่ชัด (หน้าไหน ฟีเจอร์ไหน environment ไหน?)
- ความต้องการขัดกับกฎที่มีอยู่ในไฟล์นี้
- การเปลี่ยนแปลงแตะมากกว่า 3 ไฟล์ หรือข้ามหลายฟีเจอร์
- กำลังจะตัดสินใจเชิงสถาปัตยกรรม (rendering strategy, lib ใหม่, schema design)

ถามทีละคำถามที่เป็น blocker จริง อย่าถามสิ่งที่อนุมานได้จาก context

### Step 2 — Plan, then present for approval
ก่อนเขียนโค้ดหรือรันคำสั่งที่แก้ไฟล์:
1. บอกเป็นภาษาคนว่าจะทำอะไร (ไฟล์ที่จะสร้าง/แก้, คำสั่งที่จะรัน)
2. ระบุ assumptions ที่ตั้งไว้
3. **รอการอนุมัติชัดเจน** ("go ahead", "do it", หรือเทียบเท่า)

อย่าตีความความเงียบหรือคำถามตามมาว่าเป็นการอนุมัติ

### Step 3 — Implement
ทำหลังได้รับอนุมัติเท่านั้น แล้วรัน lint + test ของ stack นั้น

### Step 4 — Report
แสดงว่าอะไรเปลี่ยน (ไฟล์, การตัดสินใจสำคัญ) และผล lint/test
อย่าสรุปว่าโค้ดทำอะไร — แสดงหลักฐานว่ามันทำงานได้
